# Protected span attributes: browser query design

## Boundary and contract

Alloy stores a selected string span attribute `password` only as `enc.password` with an authenticated deterministic string value. Tempo indexes and compares that **same stored field**; it has no key and needs no change. Grafana's browser translates an explicit plaintext comparison such as `{span.enc.password="abc"}` into a comparison against the ciphertext before sending it to Tempo. The editor may show the plaintext *locally*, but a protected literal must never enter a saved Grafana query model: the stored raw query or protected builder value is sealed separately before the host's `onChange`. There is no secondary equality field or server-side translation. This design covers model persistence and the outbound query/metadata boundary; [the crypto and display design](./protected-attributes-crypto-ui-design.md) owns key import, both cryptographic domains, and response decoding. Its [frozen attribute byte contract and public vectors](./protected-attributes-crypto-ui-design.md#frozen-bytes-and-browser-crypto) are the durable frontend reference. The distinct query-model seal below is **not** a Tempo span attribute.

For protection, the datasource stores only `jsonData.protectedAttributesEnabled: true`, not the secret or a required key ID; its other existing configuration is unchanged. Each browser-imported `ProtectedAttributeKey` has `kid`, `encrypt(storedField, plaintext)`, `decrypt(storedField, envelope)`, `clear()` and separate async model-sealing functions; `importKey(base64)` is async. `src/datasource.ts` owns a map of imported keys by `kid`, exposes `protectedKeys`, `getProtectedKey(kid)`, `protectedKey` as the current editor key, `protectedKeyEpoch` and `subscribeProtectedKey(listener)`. `importProtectedKeys(base64Keys, signal?)` validates a batch before adding/replacing only matching IDs; `importProtectedKey(base64)` imports one. `clearProtectedKey(kid?)` forgets one key and `clearAllProtectedKeys()` forgets all. Import derives each `kid` from valid key material; failed or superseded imports leave existing keys unchanged. Notify subscribers on successful import and forget; stale import, response-decode, seal and editor-open completions cannot restore forgotten keys or plaintext. Query code calls `key.encrypt('enc.password', 'abc')`, never reimplements HKDF/AES-SIV. Its result must equal `enc:v1:630dcd2966c4336691125448bbb25b4f:7aUwjY5fPtHvu_dUnzcxBJc6XQ` for the public test key in the linked contract. Determinism leaks equality/frequency and length; historical `!=` is complete only when the browser holds keys for every relevant stored key ID.

A protected reference means a TraceQL attribute whose **decoded span stored name** begins `enc.`. The only supported exact predicates are explicit **span-scoped** attributes on the left of `=` or `!=` and a single double-quoted literal accepted by the pinned Lezer parser on the right; opt-in substring has a separate contract. An unprefixed `span.password` is ordinary TraceQL: do not infer sensitivity, rename it, or promise protection. A protected projection (`select(span.enc.password)`) is allowed without a predicate. A configured datasource with no imported key may run ordinary *unsealed* queries and fetch traces; a sealed protected query is locked, and a newly entered protected predicate fails locally with a value-free error and makes **no request**. Stock Grafana trace/search DataFrames always retain ciphertext. An enabled Tempo datasource displays `[encrypted: key unavailable]` for a canonical protected value lacking its key and `[encrypted: invalid data]` for an authenticated-resolution failure; matching keys decrypt rendered span text in stock TableNG and Tempo span detail/summary. Noncanonical strings currently fall back to raw formatting.

**Current key-selection contract:** a sole imported key is automatic; with multiple keys, choose one per protected predicate in Raw or Builder mode. Raw models retain nonsecret `protectedQueryKeys` identities/key IDs; Builder filters retain `protectedKeyId`. The model-sealing key is independent of these search keys. Predicate edits invalidate their choices; unchanged unambiguous raw predicates can rebase to new offsets. Missing/forgotten selections reject before dispatch, including contextual metadata. Selection metadata and local key names never enter transport. There is no automatic historical-key union: equality can miss other-key rows, and inequality can include equal plaintext encrypted under another key.

## Strict saved-model boundary

The Grafana host owns `TempoQuery` persistence: today `src/traceql/TraceQLEditor.tsx:46-48` calls `onChange({...query, query: value})`, and `src/SearchTraceQLEditor/TraceQLSearch.tsx:54-71` calls `onChange` with plaintext `filters[].value`. Dashboard saves and Explore state may serialize these models to the Grafana backend independently of Tempo requests. Therefore rewriting only `super.query()` is insufficient. `src/QueryField.tsx` and its children must never pass an unsealed protected value to host `onChange`, even temporarily during typing, key import, query-option updates or tab changes. Plaintext may exist in local component/Monaco drafts while the key is loaded; unmount/clear drops those drafts. This protects plugin-controlled model writes, not old already-saved plaintext dashboards or host-owned ad-hoc/template-variable state.

The crypto/UI owner adds `ProtectedAttributeKey.sealQueryModel(plaintext: string, context: string): Promise<string>` and `openQueryModel(envelope: string, context: string): Promise<string>` to its key interface. The linked crypto design specifies the independent HKDF-SHA256/AES-256-GCM domain: HKDF salt `tempo-query-model-v1`, info `aes-256-gcm`, 32-byte nonextractable Web Crypto AES key, fresh 12-byte nonce, 16-byte tag, and `qenc:v1:<kid>:<unpadded-base64url(nonce || ciphertext || tag)>`. Its AD length-frames a UTF-8 context after `tempo:query-model:v1` and a zero byte, separate from deterministic `enc:v1` span values. The canonical context is `JSON.stringify([uid, 'query'])`, `JSON.stringify([uid, 'filters', filterId, 'value'])`, or `JSON.stringify([uid, 'filters', filterId, 'value', indexAsDecimalString])` for an array item; `uid` and filter IDs are nonempty and filter IDs unique. No `refId` is bound, so copied queries retain their field binding. Never call span `encrypt('enc.password',...)` for model storage, use a model envelope as a TraceQL RHS value, or persist derived key bytes. Unknown model version, kid/context mismatch, truncated nonce/tag and failed authentication lock that field and never reveal bytes as plaintext. Model sealing is async; the editor ignores out-of-order completions or a completion after key clear/datasource change.

In query-owned `src/protectedAttributes/model.ts`, define `prepareProtectedQueryModel(draft, key, datasourceUID): Promise<TempoQuery>` and `openProtectedQueryModel(model, key, datasourceUID)` as conceptual APIs, with `assertProtectedQueryModelSafe(query: TempoQuery, kid: string): void` as a synchronous host-write gate used by crypto/UI's `QueryField.tsx`. The actual helpers may split raw and builder paths, but must enforce the same invariants:

- For a **valid raw TraceQL** string, inspect the pinned Lezer AST *before host `onChange`*. If it references `enc.` **or has a variable-bearing attribute name/scope or query fragment that could resolve to `enc.`**, seal the **entire original editor query** into `query.query` with the `query` model context before calling host `onChange`. For example, `{span.${attribute}="abc"}` must seal `abc` even if `${attribute}` currently resolves to `http.route`: its future value may be `enc.password`. This conservative classification may require a key for an otherwise unprotected dynamic-name query, but does not drop the query. A valid fixed-name query with no protected reference remains ordinary plaintext so fixed-field nonprotected editing/querying stays keyless. Missing key, unsupported protected operation, parser recovery, incomplete/ambiguous syntax or a pending async seal keeps the draft only in component state; **never publish a raw intermediate draft**. Do not infer safe persistence from the variable's current value or a substring scan. A trace ID remains on its unprotected path.
- A `traceqlSearch` builder seals each explicit protected span filter value and **each value whose tag/scope is variable-bearing and could resolve to a protected span field**, one model envelope per scalar/array element with filter-ID and index context. The tag/scope itself may remain as a nonsecret variable reference; a current nonprotected resolution does not make its adjacent value safe to persist plaintext. Fixed-name nonprotected filters retain ordinary values/keyless editing. After import, open locally, interpolate the tag/scope and check the effective attribute before choosing protected-RHS translation; if the RHS resolves from a host variable when the effective field is protected, reject it. Before changing tag/scope, clear or safely reseal an adjacent value atomically; never carry `qenc` into an unprotected field as a literal. Missing key, unsupported scope/operator, bad value and pending seal keep the draft local; host `onChange` receives only the fully safe model. The existing `SearchField` tag/scope reset is a starting pattern, not the sole gate.
- The gate checks protection policy, model-envelope syntax, query AST classification, variable-bearing attribute identifiers/scopes/fragments, builder filter tags/scopes/values and legacy plaintext carriers on **every** `QueryField` parent `onChange` (including option toggles and migration). It accepts valid statically named ordinary raw queries and fixed-field unprotected builder values unchanged; it requires qenc for explicit protected **or potentially protected through dynamic names** query/filter values. It rejects unsealed or malformed qenc, ambiguous syntax, unsupported protected use and legacy plaintext search fields. A synchronous check is not a substitute for authenticated `openQueryModel` before editing/dispatch. An old saved plaintext model containing an explicit or dynamically possible protected reference is a migration error: do not forward, display as editable-but-safe plaintext, or silently re-save it. Require explicit secure re-entry/migration after key import; old dashboard history/URLs must be audited separately because rewriting a current model cannot erase earlier server copies.
- `QueryField.tsx` subscribes to the datasource's non-secret `protectedKeyEpoch` on mount and unsubscribes on unmount. Every mounted editor for that datasource remounts on UID/epoch change, dropping component/Monaco drafts; controls call the model gate and do not run a pending seal, while late async completion must not persist an older draft. Locked sealed queries/filters without a matching key render masked/read-only, never `qenc` as editable plaintext. After key import, `openQueryModel` restores only component-local editor values. `src/traceql/QueryEditor.tsx` copy-from-Search must seal its newly generated protected query before host `onChange`; `TraceQLEditor.tsx` must stop directly forwarding each keystroke, and `TraceQLSearch.tsx` must build contextual metadata from *opened local filters*, not stored `qenc` values. `QueryField.tsx` also gates render-time `nativeSearch` migration through the same model validator/sealer; it must never re-save a legacy plaintext protected model.

At dispatch, detect `qenc` by its **model envelope grammar**, authenticate/open it with the imported key and correct slot context, then inspect variable provenance, interpolate allowed variables, validate/rewrite the resulting TraceQL and construct a sanitized transport-only request. Similarly open protected or dynamic-name builder values **before** `generateQueryFromFilters`; never encrypt an already-sealed value as original plaintext, use a model seal as a search RHS, or mutate the host model with outbound `enc:v1` bytes. For a newly protected field after dynamic-name interpolation, its literal is safe only if it came from the opened qenc model, **not** from host variable substitution; reject a protected RHS or complete protected expression supplied by a host variable. If interpolation unexpectedly introduces `enc.*` from an unsealed ordinary model, reject rather than translating a value that was already saved plaintext. Without a matching key, reject a sealed query before HTTP/Live/metadata. `applyTemplateVariables()` and `interpolateVariablesInQueries()` are synchronous host hooks in `datasource.ts`; with protection configured, they must not return an opened plaintext protected query/model to the host or expand a variable into an unsafe unsealed model. Defer safe interpolation to async client-side dispatch. `getQueryDisplayText()` returns a redacted/locked label for sealed content, never an opened query to host logging. Fixed-name ordinary unsealed queries retain existing behavior.
The provenance rule covers **every** variable expansion site, not only an original protected RHS or dynamic attribute name. A fixed unprotected saved query such as `{span.http.route=$value}` may become `{span.http.route="x" || span.enc.password="secret"}` if the host supplies `$value` as `"x" || span.enc.password="secret"`; the new protected predicate was never sealed in a plugin-controlled model. Reject it locally even if the final TraceQL parses and the key could encrypt `secret`. A variable inside an originally quoted literal can likewise escape its quote or alter predicate structure if substitution is not context-safe. Inspect the source/model and provenance of replacements before interpolation, then parse/classify the final AST; reject if host-supplied bytes create a protected predicate, protected RHS literal, or surrounding expression structure rather than a pre-existing authenticated model-origin predicate. **Narrow allowed case:** inside an opened `qenc` model, a variable occupying only an existing attribute-name/scope node may resolve to a protected span identifier (`span.${attribute}` → `span.enc.password`) if its substitution is identifier-only, the predicate structure is unchanged, and its literal RHS is from that authenticated model. The equivalent builder tag/scope variable requires its adjacent value to have been sealed. Reject the **whole** request before HTTP, Live, metrics or contextual metadata `q` otherwise. Ordinary host substitutions that cannot introduce protected syntax retain their current behavior.

## Parser and rewrite algorithm

`src/protectedAttributes/traceql.ts` is the single async outbound compiler: `rewriteProtectedTraceQL(query, keys, mode, substringEnabled, selections)`. Protection must be enabled; unconfigured datasources retain their behavior. It receives finalized, interpolated TraceQL and predicate-bound key choices, not a saved model. It returns a new string without changing editor state or emitting telemetry. Use the pinned Lezer AST and source offsets to identify comparisons, never regex replacements or matches inside comments/string literals.

1. Parse once. Traverse comparison expression nodes and relevant attribute consumers (select, by/grouping, arithmetic). Collect syntax error/recovery nodes (`type.isError` or error id 0), incomplete nodes, and source ranges. For a protected datasource, malformed TraceQL **fails locally**, including parser recovery that might hide a protected reference; do not forward the partially translated original. Trace IDs and empty requests follow their existing dispatch paths and are not TraceQL parsed. Do not claim a regex precheck can prove a malformed input safe.
2. Determine the attribute's scope and decoded name from parser structure. Preserve the original source spelling on the left. Dots may be in quoted or unquoted identifier components: `span.enc.password`, `span."enc.password"`, and `span.enc."password"` identify the same stored key `enc.password`. Decode quoted *identifier* escapes according to TraceQL (`\"` and `\\`), not a greedy prefix regex. Reject `resource.enc.password`, `.enc.password`, `parent.span.enc.password`, `event.enc.password`, `link.enc.password`, instrumentation and intrinsic/other scopes rather than silently treating them as span references. Only names equal to the decoded stored name are encrypted; `span.password` is not.
3. Require the protected node to be the **direct LHS** of `=`/`!=` in a spanset predicate (`FieldExpression` containing `FieldExpression(AttributeField)`, `FieldOp`, `FieldExpression(Static(String))` in pinned Lezer 0.0.25), with a single complete RHS double-quoted literal. Decode its lexeme as a JSON-compatible string **within the Lezer-supported subset**: `"123"` means the three characters `123`, `""` means empty, raw Unicode and the escaped characters `\"` and `\\` are accepted. The pinned `stringDouble` grammar permits only those two backslash escapes, even though Tempo's Go parser supports more. Reject `\n`, `\t`, `\uXXXX` and every other unsupported escape, raw control characters and parser recovery locally, without forwarding the original to Tempo. Do not promise searches for control-containing plaintext in v1; inform users at input. Reject numbers (including `123`), boolean, nil, backticks, arrays, other attributes, functions, arithmetic, reversed equality (`"abc" = span.enc.password`) and incomplete literals. Reject `=~`, `!~`, `<`, `>`, `<=`, `>=`, arithmetic, grouping **by the protected value**, and any other non-predicate protected use. Do not attempt a useful-looking plaintext fallback. Local errors contain field/operation guidance but **never quote the plaintext, whole query, key, envelope, or backend error body**.
4. For each protected plaintext predicate, call its selected `key.encrypt(decodedStoredField, decodedLiteral)`; preserve unrelated syntax and original LHS spelling. A sole loaded key is automatic. A canonical stored `enc:v1` literal passes through without a key; other envelope-like strings are not granted that exception. Compile only at the outbound boundary.
5. `!=` needs an existence guard. Make **one** replacement for the whole comparison's AST `[from,to)` range, constructing `(original-LHS != encrypted-RHS && original-LHS != nil)` from its exact source slices and the new quoted envelope. This is the only permitted change outside the protected RHS; the original LHS spelling/operator are retained. Parenthesize to preserve surrounding boolean precedence, including `||`, nested parentheses and multiple `!=` predicates. Batch only non-overlapping edits and apply right-to-left so earlier offsets remain valid; do not separately edit an RHS already inside a replaced comparison. `nil` is valid only in this generated guard; a user-written protected comparison to `nil` remains unsupported. If an AST shape cannot be bounded safely, reject before any network call rather than modifying a substring heuristically. `=` needs no guard. This guard prevents a span lacking `enc.password` from satisfying inequality.
6. In **search** mode, collect the distinct protected stored fields referenced by predicates and ensure their ciphertext values are fetched with `| select(span.enc.password, ...)`. If a select already exists in the relevant pipeline, add missing fields to its argument list at AST-derived offsets without duplicating existing equivalent quoted/unquoted fields; preserve the other selected fields. Otherwise insert a select at the end of a compatible spanset pipeline, **before** a trailing `with (...)` query hint. Do not attach a select after an aggregate or across separate branches where its effect cannot be established; fail locally for an unsupported search pipeline shape. Existing explicit `select` with no protected predicate stays unchanged. In **metrics** and **metadata** modes do not add a display projection; metrics may filter on a protected field but may not group by, perform arithmetic on, or expose the protected value as a label. Validate the final rewritten TraceQL to catch invalid insertions.

Example search (whitespace here illustrates semantics, not a promised serializer):

```traceql
{span.enc.password="abc" || span.enc.password!="π🙂"}
→ {(span.enc.password="<envelope abc>" || (span.enc.password!="<envelope π🙂>" && span.enc.password!=nil))} | select(span.enc.password)
```

The implementation uses actual envelope bytes from `encrypt`, not those illustrative placeholders, and preserves valid original formatting outside edits. A pre-existing `| select(resource.service.name)` becomes `| select(resource.service.name, span.enc.password)`; no duplicate if it already selects the protected field.

## Outbound call sites and failure atomicity

`src/datasource.ts` currently dispatches `traceql`, `traceqlSearch`, `nativeSearch` migration, trace IDs and metrics from `query()`. First validate every visible saved model: reject legacy plaintext protected references, malformed qenc and host-owned protected ad-hoc filters. Open sealed raw queries and builder values only in browser memory with the imported key, then interpolate *allowed* variables, generate final TraceQL and compile **each** final query before dispatch or telemetry. One bad target stops the whole grouped request; never send another target first. Make async preparation part of the returned Observable (e.g. `defer`/`from` and `mergeMap`) and map local errors to a value-free datasource response. Keep host models unmodified. **Do not spread a full editor target into a protected transport request**: `filters[].value`, `options.filters`, deprecated `search`/`spanName`/`serviceName`, original `query`, `serviceMapQuery`, model `qenc` and template-variable values in `options.scopedVars` can carry protected plaintext or unrelated secrets. Construct an allowlisted *request-only* Tempo target after compilation with `refId`, `queryType`, compiled `query`, and only the execution controls needed by that branch (such as `limit`, `spss`, `tableType`, metrics type/step/exemplars and datasource identity); remove raw filter arrays and legacy string fields. Build an allowlisted `DataQueryRequest` with range/app/request ID/interval/timezone operational fields but **without raw `options.filters`, `scopedVars` or original targets** after interpolation. Check any additional backend-required field individually before admitting it to the allowlist. Audit the **entire serialized HTTP body and Live `data` object**, not only `target.query`. Avoid validating only `targets.traceql[0]` then forwarding later raw targets. Final search/metrics classification uses the query actually dispatched; no uncompiled second target escapes via another branch.

`src/language_provider.ts` handles `tags`, `tag-values`, contextual `q`, `getTagValues`, `tagValuesQuery`, `labelValuesQuery` and ad-hoc tag discovery. **When protection is configured**, keep `enc.*` **tag names** visible in the raw/Query Builder editors, but suppress protected span tag **values** at `getOptionsV2` before sending the `tag-values` request, including autocomplete, Search builder and variable callers; do not populate caches with ciphertext suggestions or silently decrypt frequency dictionaries. Unconfigured datasources retain their existing metadata behavior. `src/traceql/autocomplete.ts` and `src/SearchTraceQLEditor/SearchField.tsx` both consume `getOptionsV2`. The protected Search editor allows manual values in its local draft and explains that no protected value suggestions exist. Contextual `q` for another tag may include a locally opened protected predicate; encrypt at metadata boundary or reject with no key. Fetching tag names needs no key.

`src/SearchTraceQLEditor/SearchField.tsx` currently infers numeric/boolean custom values without metadata type; `src/language_provider.ts` ad-hoc serialization treats integer-looking values as bare. Override builder serialization for **explicit** `span.enc.*` only: `"123"`, `"true"` and empty are protected strings; quote and backslash escape as `\"`/`\\` in a double-quoted TraceQL literal. Raw Unicode is allowed. A value requiring a control-character escape (`\n`, `\t`, `\uXXXX`, etc.) is **not representable in the pinned frontend grammar** and fails locally with a value-free explanation, rather than emitting an invalid or plaintext protected query. A protected filter with regex/ordering/unsupported scope is rejected before sealing or dispatch even if a generic Select permits it. Multi-value `=`/`!=` builder filters serialize to independent predicates joined by `||`/`&&`; open and interpolate each local value, encrypt each RHS once, guard each `!=`. Fix serialization at `src/SearchTraceQLEditor/utils.ts` where needed. Host-owned ad-hoc numeric serialization remains unchanged for unprotected fields only.

### Host-owned ad-hoc and template variables

`TempoDatasource.getTagKeys()` and `getTagValues()` in `src/datasource.ts:224-255` only return suggestions; `query(options)` receives `options.filters` from Grafana and has no write hook for the host ad-hoc variable model. Grafana's [ad-hoc persistence issue #117639](https://github.com/grafana/grafana/issues/117639) describes `AdHocFilterItem` as raw `{key,value,operator}`, the persisted dashboard `AdHocFilterWithLabels`, and panel actions that can add values without a datasource `getTagValues` call. Returning `MetricFindValue {text: plaintext, value: qenc}` would still let the host persist plaintext labels, custom values or panel-inserted filters; this plugin cannot provide a guaranteed browser-local display label and a sealed persisted value for *all* Grafana-owned entry points. The **user-approved v1 fail-closed restriction** is therefore: omit protected span `enc.*` keys from `getTagKeys()` *for the host ad-hoc picker only*, reject a protected key in `getTagValues()` and any existing `options.filters`/contextual metadata filter targeting `enc.*` **before** any backend call, and display a value-free instruction to use the Search builder or raw TraceQL instead. Do not silently ignore an existing protected filter; old already-saved host variables need manual removal/audit. Ordinary ad-hoc filters continue to combine with raw/builder queries and are stripped from the Tempo transport after their values have been serialized into the compiled query.

**Display boundary:** the locally built Grafana host decrypts only the rendered text of Tempo `enc.` span values in stock TableNG and TraceView. Raw DataFrames, trace tags, field config, data links, host ad-hoc filters and saved models retain ciphertext. The datasource supplies a browser-only resolver at `Symbol.for('grafana.tempo.protected-attribute-display.v1')`; the host calls it only for a complete canonical envelope and the actual stored field name. The nested Traces table and direct trace-ID span detail display authenticated plaintext with a loaded key; resource/event/link attributes, Raw JSON and unmodified renderers do not. Table and trace actions receive raw ciphertext, except explicit local Copy of the visible TraceView value. A panel-created ad-hoc filter therefore copies ciphertext, not decrypted text. Users must not manually type protected plaintext into host ad-hoc variables, which this plugin cannot seal.

`getTemplateSrv().replace` and `interpolateFilters` can substitute Grafana-host variable values into a protected RHS **or attribute name**. Host variable values may already live in saved variable or URL state beyond this plugin's sealing boundary. **Reject an actual host template variable on a protected RHS before interpolation**, in raw TraceQL and builder values, including contextual metadata. A dynamic attribute name/scope (`span.${attribute}`) or query-fragment variable may later introduce `enc.*`: seal the original entire raw query before host persistence even when the current expansion is unprotected, and seal the adjacent builder value for a dynamic tag/scope. Once opened, interpolate names locally and apply the normal protected compiler; reject if host variable substitution itself introduces protected plaintext RHS or a whole protected expression. Plain `$` text not resolved as a variable remains an ordinary literal. Template variables in values of fixed-name *unprotected* predicates remain supported and are interpolated locally before the compiler. No original host `scopedVars` enters HTTP/Live request or interaction payload. Protected values are entered through plugin-owned raw or Search builder local drafts, not Grafana template/ad-hoc value inputs.
This also applies when the variable was placed at an ordinary unprotected value site: an unquoted `$value` (or a string variable that escapes its literal) can inject `|| span.enc.password="secret"` into the resulting expression. Original-query classification alone cannot detect that attack. An injected `enc.` reference in a final AST is not automatically legitimate merely because some other protected predicate in the same opened model was authenticated. Preserve enough source provenance to attribute **each** protected AST predicate and RHS, while allowing only identifier-confined dynamic name/scope substitution in an opened sealed model with an unchanged predicate and model-origin RHS. Reject host-supplied syntax or literals rather than encrypting them. Apply the same guard to contextual metadata `q` before `getResource()`.

`TempoJsonData.search.filters` is a different, admin-configured persistence path: `src/configuration/TraceQLSearchTags.tsx:38-48` writes filter defaults to datasource `jsonData.search.filters`, and `TraceQLSearch.tsx:98-106` copies valued defaults into a query model. The crypto/UI owner must reject a valued static filter whose **effective or potentially dynamic** scope/tag can target a protected `span.enc.*` attribute before `onOptionsChange`: this includes explicit `span.enc.*`, a variable-bearing tag/scope such as `scope: span, tag: '${attribute}'`, and any unresolved query fragment. An admin configuration writer has no browser-imported key with which to seal that value, so do not save it under a currently nonprotected variable resolution. The query owner must also fail closed at runtime when provisioned settings bypass the UI. Never copy its plaintext value to the query model, contextual metadata or transport. Statically named ordinary filters remain supported. Existing plaintext configuration cannot be retroactively removed by frontend validation and needs admin cleanup.

`src/QueryField.tsx` currently gives `QueryWithAssistantButton` the raw `currentQuery` and `queries` objects; this is a separate possible exfiltration path, not fixed by HTTP/Live compilation. Crypto/UI owns this file and must **disable the assistant handoff whenever protection is configured**, regardless of key-loaded state, until a separately reviewed sanitized context design exists. Do not give the assistant a query with protected plaintext or a copied key. The query owner verifies this acceptance with the UI owner without editing `QueryField.tsx`.

## Telemetry, response handoff and security

`datasource.ts` currently sends interpolated plaintext as `query` in `grafana_traces_traceql_queried`, `_metrics_queried`, `_search_queried` and response metrics (`reportTempoQueryMetrics` in success/error/Live `finalize`). For configured protected datasources, **remove query text from every interaction and response event**, including failed/aborted requests. Do not substitute ciphertext for telemetry; it reveals equality and is unnecessary for these events. Do not attach raw request targets or error strings/statusText/backend error bodies that may echo a query to interactions, logging, exception reports or custom analytics. Retain safe app/version, success, streaming, time range, latency and numeric status. The normal UI can show a sanitized local error; backend transport receives only compiled ciphertext and may report its own errors. Key bytes/import input never belong in `jsonData`, `secureJsonData`, saved query models, browser storage or telemetry. For explicitly protected fields, saved plugin-controlled models contain only authenticated `qenc` values; ordinary unprotected query/filter strings remain plaintext as before. Host-owned ad-hoc/template RHS protection and old saved models follow the fail-closed limitations above. No server-side key means server-rendered alerting/direct Tempo callers cannot transparently open model envelopes or translate protected literals; a browser key is required.

`src/protectedAttributes/display.ts` owns the browser registry and resolves protected values synchronously by the ciphertext's key ID from the imported key set; `src/datasource.ts` registers protection policy and updates that key set on import/forget. It increments the registry epoch and emits a detail-free change event to rerender stock cells. `src/streaming.ts` and HTTP query handling return encrypted frames without extracting or storing per-response plaintext. Live search normalizes a nullish result to `[]` before formatting; `src/resultTransformer.ts` remains unchanged. The host display hook, not a response extractor, is the only path from ciphertext to rendered plaintext.

A deterministic single-value `=` is native Tempo indexed search. This design deliberately rejects regex/fuzzy/ordering of encrypted plaintext, searches of unprefixed names, and silent server-side fallbacks: none preserve the one-field authenticated exact-match contract. Explicit selects are merged rather than replaced so existing projections retain their meaning. Without a key, ordinary unsealed query dispatch remains available; a sealed protected model is locked and no protected predicate, ad-hoc filter or template RHS is sent in plaintext.

## Observable acceptance checks for implementation

- With the matching shared **symmetric master key** imported into the browser, raw and Search builder `{span.enc.password="abc"}` yield the exact attribute envelope on **`span.enc.password`** for HTTP and Live search, plus `select(span.enc.password)` in search. The editor keeps plaintext only in keyed local drafts; host query models store separate `qenc:v1` ciphertext and returned frames/tags remain encrypted. The stock nested Traces table and Tempo span detail display `abc` while the key is loaded, including direct trace-ID results; Forget masks it without changing raw frames. Reopen with a matching key restores editing; no key/mismatched kid locks protected fields and sends no protected request. Plain `{span.password="abc"}` and unprotected ad-hoc/template queries remain ordinary and keyless. Metrics predicates encrypt without a select.
- Two or more protected values, empty, raw Unicode, `"123"`, escaped quotes/backslashes, dotted/quoted stored names and multiple targets compile without changing unrelated query text. `!=` excludes missing fields, including inside an `||` branch. `\n`, `\t`, `\uXXXX`, control-containing protected builder drafts, unsupported operators and ambiguous/incomplete AST remain unsaved drafts or fail before outbound request. Metadata contextual `q` opens locally and encrypts once; protected tag-value metadata never suggests ciphertext. Variable-bearing attribute names/scopes or query fragments seal the **whole raw model**, and dynamic builder tags/scopes seal their adjacent values before host `onChange`; test a later variable flip from `http.route` to `enc.password` and verify no saved plaintext. A valued static datasource default with explicit `span.enc.*` **or variable-bearing tag/scope** is rejected in ConfigEditor and at runtime. An actual host template value on a protected RHS, a host-supplied protected query fragment and an existing protected host ad-hoc filter fail closed; fixed-name unprotected host value variables/ad-hoc filters still work.
- Protected prefixed regex, ordering, arithmetic, group-by use, non-string/nil RHS, wrong scope, reversed comparison, missing/malformed syntax, and key missing/mismatched all fail before `super.query()`, `getResource()` or `getStream()` receives the original. A plain `{span.password="abc"}` remains unchanged and is not misrepresented as protected.
- Given a fixed unprotected saved query `{span.http.route=$value}`, substitute a host `$value` that yields valid TraceQL `"x" || span.enc.password="secret"`; assert **zero** HTTP, Live and metadata calls containing or derived from `secret`, including when another authenticated protected predicate appears elsewhere in the query. Repeat with a substitution escaping an originally quoted ordinary string, a variable-bearing query fragment and a protected expression in contextual metadata `q`. Conversely, an opened sealed `{span.${attribute}="abc"}` with identifier-only `${attribute}` → `enc.password` translates its model-origin RHS, while a variable inserting operators/predicates or supplying its RHS fails. Harmless ordinary variable expansion remains supported. The guard attributes each post-interpolation protected AST predicate/RHS to authenticated browser-opened model text, except the identifier-confined dynamic name/scope.
- Capture host `onChange` and save/Explore query models across raw typing, builder edits/multi-value changes, query-type switches, Search-to-TraceQL copy, key import/clear, concurrent seal completion, runtime static defaults and legacy model migration: no protected plaintext reaches `TempoQuery.query`, protected `filters[].value`, datasource `jsonData.search.filters`, query-assistant context, or persisted host variables through plugin-controlled writes. Model `qenc` ciphertext differs from the deterministic Tempo `enc:v1` equality envelope and rejects tampered/wrong-slot data; keyless ordinary queries remain functional. Capture the **whole** HTTP request (including each target, `filters` and `scopedVars`) and Live `data` payload: no original editor target, protected plaintext, model `qenc` or key bytes reaches Tempo. Capture `reportInteraction` success/failure and assert no query/envelope/error echo. For trace-ID, HTTP Traces/Spans/Raw, search nested frames and Live, inspect every host-visible frame/tag/field config: protected values remain ciphertext and unrelated values/layout remain intact; only the plugin pane displays decrypted values or prescribed placeholders. Confirm host panel ad-hoc actions can see/copy ciphertext only, manually entered protected host ad-hoc filters fail locally, stale HTTP/Live completions cannot repopulate a cleared/newer pane, and mixed target responses retain each target's pane entries. Crypto/UI owns rendering proof; query owner verifies HTTP/store handoff.

No validation commands are run during this design-doc gate; these are future doer/integration acceptance checks, not claims of observed runtime behavior.

## Open implementation verification questions

Before coding, inspect pinned `@grafana/lezer-traceql` node offsets and Tempo syntax for `span."enc.password"`, nested `!=` and trailing `with (...)`; the reviewed grammar confirms only `\"` and `\\` escapes in double-quoted literals, and Tempo supports `!= nil` and select before a trailing hint. If a supported query cannot be rewritten with exact AST offsets and valid Tempo syntax, constrain it with a value-free local error and raise the precise limitation to Main during review. Confirm whether multiple select operations or structural branches have a single safe projection target; otherwise reject the protected search locally. **Known migration limit:** existing saved plaintext protected queries, Grafana host ad-hoc/template variables and prior datasource static defaults may already be present in Grafana backend/history; this plugin cannot erase them retroactively. Strict v1 blocks their reuse/saving, requires operator cleanup/migration, and keeps ordinary unprotected host paths. Future protected Grafana ad-hoc/template support requires a host persistence hook or reviewed custom UI that seals every input, custom/panel action and displayed label **before** Grafana owns the state; `getTagKeys/getTagValues` suggestions alone are not such a hook. No doer starts before the paired reviewer and Main accept this strict boundary.
