# Browser crypto, key UI, and display of protected Tempo attributes

## Decision and boundary

The Tempo datasource stores each selected span attribute under one `enc.`-prefixed field with an authenticated, deterministic envelope. The browser encrypts protected query literals and decrypts returned values only while stock Grafana Explore components render them. Tempo and the Grafana backend receive neither the key nor display plaintext; Grafana-owned DataFrames, trace models, filters, links, and saved queries retain ciphertext. There is no `enc_eq` field, auxiliary index, backend decryptor, or persisted browser key. The [query design](./protected-attributes-query-design.md) covers the outbound query grammar and saved-model boundary.

The administrator configures `TempoJsonData.protectedKeyId?: string`, a public 32-character lowercase hexadecimal key fingerprint. A user imports the matching 32-byte key in Explore. Without it, protected literal queries fail before network dispatch and registered protected values render `[encrypted: key unavailable]`. Use one key per datasource and queryable retention window; mixed `kid` values and multi-key `!=` are not supported.

## Frozen bytes and browser crypto

- Decode a base64 text/file input, allowing padded or unpadded standard base64 and trimming only surrounding whitespace. Reject invalid characters, malformed padding and decoded lengths other than **32 bytes**. Do not accept a password/passphrase as a key.
- Compute `kid = hex_lower(SHA-256(master)[0:16])`. Web Crypto `subtle.digest` computes SHA-256; `subtle.importKey('raw', master, 'HKDF', false, ['deriveBits'])` and `deriveBits` produce **64 bytes** using HKDF-SHA256 with IKM=`master`, salt UTF-8 `tempo-attr-v1`, and info UTF-8 `aes-256-siv`. Fail import if Web Crypto is unavailable (ordinary HTTP outside localhost is not a supported secure context). Keep the derived bytes in the browser to use AES-SIV; a non-extractable Web Crypto AES key cannot implement this scheme.
- Pin a compatible `@noble/ciphers` version and import `aessiv` from `@noble/ciphers/aes.js`. Use RFC 5297 AES-256-SIV with that 64-byte derived key, one associated-data component, no nonce. Associated data for *each actual stored field name* is `UTF8('tempo:span:v1') || 0x00 || uint32be(byteLength(UTF8(storedField))) || UTF8(storedField)`. Use the exact bytes of `enc.password`, `enc.token`, etc., not the original name `password`. Encode plaintext with UTF-8; empty string is valid. The output bytes are the 16-byte SIV followed by ciphertext.
- The string stored in `enc.password` and used as a search equality literal is exactly `enc:v1:<kid>:<base64url_no_padding(SIV || ciphertext)>`. Reject unknown versions, bad syntax or base64url, truncated SIV, incorrect `kid`, wrong associated data/key, invalid UTF-8 plaintext, and authentication failures. Parse canonical envelopes rather than accepting alternate encodings. On success, identical key, stored name and plaintext must always produce identical envelope bytes.

The public test key is ascending bytes `00..1f`, base64 `AAECAwQFBgcICQoLDA0ODxAREhMUFRYXGBkaGxwdHh8=`; it is **not** a production key. Its `kid` is `630dcd2966c4336691125448bbb25b4f`, and its derived 64-byte key is `1bc2affe0fc67e9f1c1c597fe34bd9abab2644affb89d6af36b69fe2a1ca92cba01f1f436feac6ad9a1cb5896719b8afc6be509b6fcaa88bc7db9fcdfb41cf23`.

## Separate encryption for Grafana query models

Grafana saves `TempoQuery.query` and builder `filters[].value` to its backend as part of dashboard/Explore state. The query owner seals the **entire valid raw query only if its parsed TraceQL contains protected references**, and seals each explicit protected Builder filter value; ordinary raw queries and ordinary filter values remain unchanged and usable without a key. An incomplete or ambiguous protected draft stays only in editor-local memory until valid, never in a host `onChange`. A protected literal must **not** remain plaintext in a saved model, even though the user edits plaintext locally. Do not use the deterministic attribute cipher (`enc:v1`) or its `tempo:span:v1` associated data as a storage wrapper: a query-model ciphertext is not a Tempo attribute value and must not become a TraceQL literal. This crypto slice provides the authenticated storage primitive; AST classification and selective model serialization belong to the [query design](./protected-attributes-query-design.md).

Derive an independent **32-byte AES-256-GCM model key** from the same imported 32-byte master with HKDF-SHA256, UTF-8 salt `tempo-query-model-v1`, and UTF-8 info `aes-256-gcm`. Import it into Web Crypto as a non-extractable `CryptoKey` for `encrypt`/`decrypt`, then zero the temporary derived bytes. This domain is separate from the 64-byte AES-SIV attribute key and does not alter its frozen vectors. For *each* seal, obtain a fresh 12-byte nonce from `crypto.getRandomValues`; Web Crypto AES-GCM uses a 128-bit tag. The AAD is `UTF8('tempo:query-model:v1') || 0x00 || uint32be(byteLength(UTF8(context))) || UTF8(context)`. Encode the UTF-8 model value as `qenc:v1:<kid>:<unpadded-base64url(nonce12 || ciphertext || tag16)>`. `openQueryModel` checks canonical envelope syntax/version/kid, minimum length, context binding, GCM authentication and fatal UTF-8 decoding. On any failure, reject with a value-free error; never display an unauthenticated draft or fall back to assuming the input was plaintext. This model envelope is randomized, unlike the searchable attribute envelope.

`context` is canonical `JSON.stringify` of a string array identifying the datasource UID and exact persisted slot: `[uid, 'query']`, `[uid, 'filters', filterId, 'value']`, or `[uid, 'filters', filterId, 'value', indexAsDecimalString]` for an array item. `uid` and `filterId` must be nonempty and filter IDs unique; the array representation avoids separator collisions. Do not bind `refId`, which Grafana may change when cloning a target. Moving a sealed value to another datasource or slot must fail authentication. Clearing the handle also invalidates the model key; a non-extractable Web Crypto key reduces accidental extraction but does not protect against XSS or revoke plaintext already rendered in a component.

## Key lifecycle and display contract

`src/protectedAttributes/crypto.ts` exports `ProtectedAttributeKey` and `importKey(base64)`. Attribute `encrypt`/`decrypt` operations are synchronous after the asynchronous import; query-model `sealQueryModel`/`openQueryModel` use Web Crypto asynchronously. Each operation binds to its exact stored field or canonical saved-model slot and fails closed on a cleared key, invalid envelope, wrong key, authentication failure, or invalid UTF-8.

`TempoDatasource` exposes `protectedKey`, `protectedKeyEpoch`, `importProtectedKey`, `clearProtectedKey`, and `subscribeProtectedKey`. A mismatched import clears its new handle without replacing the current key. Successful import/replacement and clear invalidate pending imports and editor drafts, increment the datasource epoch, and notify mounted editors. A key handle stays in browser memory until cleared or the page reloads; it is never written to datasource JSON, query models, URLs, storage, cookies, backend requests, telemetry, or logs. Clearing zeroes owned key bytes and drops the model `CryptoKey` reference. JavaScript strings, already copied plaintext, browser internals, and screenshots cannot be reliably erased.

The datasource also registers its configured `kid` with `src/protectedAttributes/display.ts`. The browser-only registry is available at `globalThis[Symbol.for('grafana.tempo.protected-attribute-display.v1')]` with `{ epoch, resolve(storedField, envelope) }`. Each key import/clear increments its epoch and dispatches `grafana.tempo.protected-attribute-display-change` without key material or plaintext. For a registered key ID, `resolve` synchronously decrypts a valid `enc:v1` envelope using the actual `enc.` field name; a missing key yields `[encrypted: key unavailable]`, and invalid authenticated data yields `[encrypted: invalid data]`. Unknown key IDs return no display override. A stale datasource cannot revoke the key imported by the current owner of the same ID.

The custom Grafana host in `grafana-h/` exports `getProtectedAttributeDisplayValue`, `getProtectedAttributeDisplayEpoch`, and `subscribeProtectedAttributeDisplay` from `@grafana/data`. The helper checks the stored field and complete canonical envelope before invoking the browser registry. Stock TableNG `AutoCell` resolves a protected column only for its rendered text, including a nested Spans table inside Traces. Stock TraceView resolves only Tempo **span** attributes, both in expanded detail and collapsed summaries, including results opened by direct trace ID. It renders decrypted text as escaped React content, not HTML or auto-links. Resource/event/link attributes, Raw JSON, unrelated datasources, and other cell renderers retain their normal raw representation. Both views subscribe to key changes so Forget removes previously rendered plaintext without another query.

Grafana [issue #117639](https://github.com/grafana/grafana/issues/117639) documents Table “Filter for value” actions persisting raw DataFrame values as host-owned ad-hoc filters. For that reason, neither `field.display`, mappings, field values, nor trace tags carry plaintext. Table links and filters, TraceView extension/link inputs, query models, telemetry, and backend requests continue receiving raw ciphertext. TraceView's explicit Copy action copies the visible value locally to the clipboard; this is not a backend or saved-model write. No separate protected-values pane or per-response plaintext store remains.

## UI and response-path placement

`src/configuration/ConfigEditor.tsx` adds an administrator-facing `protectedKeyId` setting in the existing configuration sections. Validate the lowercase 32-hex-character ID when present; blank means protection is not configured. Make it clear that this public fingerprint is not the key, and that enabling protection does not encrypt existing traces. Saving writes only `jsonData.protectedKeyId`. Do **not** put a key upload or input in datasource settings, which Grafana persists. `src/QueryField.tsx` shows a compact Explore status row with Load/Replace and Forget actions; a modal accepts either masked base64 paste or a local key file, never both. The dialog shows the full expected `kid`, clears transient input on cancel/import/key change, and tells users to rerun the query after loading. File bytes are read locally only on submission and imported through the datasource bridge; the key is lost on reload. A wrong key leaves the old valid key unchanged and shows a non-secret error. Explain the visible prefixes, deterministic equality leakage, unsupported unprefixed searches, and loss of key on reload without echoing key bytes into logs, telemetry, validation errors, or DOM text outside the transient masked input.

`QueryField.tsx` currently passes the raw `TempoQuery` to `QueryWithAssistantButton`. Under the strict design, protected plaintext exists in editor-local drafts but not newly saved query models; previously saved unsafe models may still exist. Neither must be sent to a remote assistant. When `jsonData.protectedKeyId` is configured, hide/disable that button entirely, even before key import; do not rely on query translation, a conditional scan of editor text, or the assistant feature toggle to sanitize it. Unprotected datasources keep their existing assistant behavior.

The query owner keeps protected raw/Builder plaintext only in local editor drafts within `src/traceql/QueryEditor.tsx`, `src/traceql/TraceQLEditor.tsx`, `src/SearchTraceQLEditor/TraceQLSearch.tsx` and `SearchField.tsx`. It opens a sealed saved query/filter with the imported key and awaits resealing **before** any `onChange` callback can reach Grafana. Parsed ordinary queries and ordinary filters stay plain and editable without the key; only valid protected raw queries and protected Builder values use `qenc:v1`. An incomplete or ambiguous draft remains unsaved in component memory and cannot run until a valid model is committed. A sealed saved model with no matching key shows a locked, non-editable editor and an import-key explanation, not an editable ciphertext literal, plaintext fallback, or a callback that overwrites the encrypted model. Discard protected drafts on unmount, key clear or key change. Every mounted `QueryField.tsx` subscribes to its datasource's `subscribeProtectedKey` on mount and unsubscribes on unmount or datasource replacement. On any epoch notification, immediately invalidate its decrypted draft and displayed results, clear transient input, and rerender/remount raw and Builder editors keyed by datasource UID plus `protectedKeyEpoch`; do not rely on a UI-local epoch that other instances cannot observe. Block `onRunQuery` while sealing is pending; ignore a seal completion after the captured datasource epoch changes. Before *every* host `onChange`, including query-type switch, `onClearResults` and `componentDidMount`, call the query-owned `src/protectedAttributes/model.ts` export `assertProtectedQueryModelSafe(query: TempoQuery, kid: string): void` with the configured `protectedKeyId`. It AST-classifies ordinary valid queries, accepts valid `qenc:v1` envelopes with the configured kid, and rejects unsealed protected/ambiguous/legacy fields. `QueryField` must not implement a second parser.

The render-time `nativeSearch` migration and Search-to-TraceQL copy path also call `onChange`; route them through the same validator/sealing boundary. A legacy plaintext protected saved model cannot be retroactively hidden from a dashboard already stored on Grafana's backend: detect it and lock/refuse re-save or dispatch until a key-holder explicitly migrates it to a sealed model. Do not silently persist the old plaintext again.

`ConfigEditor.tsx` also prevents configured static `search.filters` from storing a protected `span.enc.*` value in `TempoJsonData` when enabling protection or saving filters. An existing provisioned static filter can bypass the editor and therefore requires the query owner's runtime fail-closed guard before generation/dispatch. Grafana-owned ad-hoc filters and template-variable values may be persisted outside `TempoQuery`; the plugin cannot seal those host-owned models. The query owner must hide protected ad-hoc keys and reject any preexisting protected host ad-hoc filter or a template-variable RHS substituted into a protected predicate, before forwarding or claiming persistence safety. Ordinary ad-hoc filters and ordinary template variables retain existing behavior. Do not silently rewrite Grafana's global dashboard variable storage.

The actual static-filter write path is `src/configuration/TraceQLSearchTags.tsx:updateFilter`, which calls `updateDatasourcePluginJsonDataOption(..., 'search', { ...filters: copy })`; its delete/initialization paths also update the same JSON. The key UI/config doer owns this file along with `ConfigEditor.tsx`: validate the full prospective `search.filters` array before each save, including retained existing filters, so a span-scope `enc.*` default with a value cannot cross `onOptionsChange`. Do not mutate the input array or silently erase invalid values. Explain the offending field without repeating its value, and allow removing the invalid filter. The runtime gate still covers provisioned JSON that bypasses the editor.

Fail closed on **valued** static defaults whose `scope`, `tag`, or embedded query fragment contains a variable/expression or cannot be resolved to an exact unprotected attribute at save time. For example `{ scope: 'span', tag: '${attribute}', value: 'abc' }` is unsafe: `${attribute}` may later become `enc.password` after the plaintext `abc` has already been saved in datasource JSON. Reject the prospective config before `onOptionsChange`, and reject provisioned equivalents at runtime; do not try to classify only the current substituted value. A value-free static tag selector may remain available if it does not carry protected plaintext.

HTTP trace-ID, HTTP search, and Live search responses keep encrypted `tags`, projected `enc.` fields, nested frames, and Raw JSON unchanged. `transformTrace` receives the original trace response; the stock span renderer resolves visible values at render time. Search formatting preserves its existing encrypted frames and metrics progress frame. Live `result: null` or an absent result is normalized to `[]` before formatting, so zero-result progress and Done events still emit. Metrics responses and uploaded traces do not invoke a response decryptor.

Metadata tag-value endpoints are owned by the [query design](./protected-attributes-query-design.md). Keep protected tag names available but suppress `enc.*` ciphertext **value suggestions** instead of decrypting metadata suggestions or exposing ciphertext as selectable plaintext. Users enter their own protected values in the query editor; the outbound query owner encrypts only supported scoped span equality/inequality RHS literals after interpolation. Do not silently make the backend a plaintext metadata service.

## Security and failure decisions

AES-SIV is deterministic so native Tempo equality works on the *one* stored field. It reveals field names, equal-value frequency and approximate length; it does not protect nonselected attributes, trace IDs or other metadata. A random 32-byte key is mandatory. The chosen key ID is public and is not an authentication secret. No backend-only alert or direct Tempo client can transparently decrypt or translate protected literals. Forget clears the imported key and local input; unmounting the query editor does not clear a still-active datasource instance. The browser display registry selects by configured key ID, not datasource UID: another datasource configured with the same ID shares that display capability until the active key is forgotten or the page reloads. Do not infer protection for `{span.password="abc"}`.

The fingerprint is SHA-256 of the raw master key, truncated to 128 bits. It is only a key-selection hint, not proof of possession or an authentication check. Publishing it permits fast offline testing of guessed keys; 32-byte input length alone does not establish randomness. Production keys must come from a cryptographically secure random generator, never a password or this public demo fixture. An independently random ID stored alongside the key would avoid exposing a hash of the master key, but changing this wire format requires a migration for existing envelopes and provisioned IDs.

A wrong configured ID is an import error and never replaces the active key. A complete canonical envelope with failed authentication or wrong field renders `[encrypted: invalid data]`; a noncanonical string stays in its raw representation because the host does not resolve it. A registered key ID with no imported key renders `[encrypted: key unavailable]`; an unknown key ID stays raw. Protected literal queries without the matching key fail before HTTP/Live dispatch. Historical mixed-key traces cannot promise correct `!=` across rotations. Errors must not contain key input or plaintext.

## Verification boundary

The public vectors above define the attribute wire format. A matching imported key displays authenticated `abc` for `enc.password` in the stock nested Traces table and Tempo span detail, including direct trace-ID results; raw frames and filter/link inputs still contain the exact envelope. Forget changes visible text to `[encrypted: key unavailable]` without rewriting those frames. A wrong field/key or altered ciphertext never displays unauthenticated plaintext. Query-model sealing remains separate: protected drafts save only as `qenc:v1`, and locked drafts cannot dispatch without the matching key.

The demo Compose build layers the Tempo plugin over the local `grafana-h/` source-built Grafana image. Rebuild both images after host or plugin changes; the published `grafana/grafana:13.1.3` image does not contain the display hook.
