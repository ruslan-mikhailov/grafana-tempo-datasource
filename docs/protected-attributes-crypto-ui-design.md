# Browser crypto, key UI, and display of protected Tempo attributes

## Decision and boundary

The Tempo datasource reads one stored string field per selected span attribute: `password` becomes `enc.password` with an authenticated, deterministic envelope as its value. The browser encrypts query literals and shows decrypted values only in a Tempo-plugin-owned Explore pane; Tempo, the Grafana backend, and Grafana-host-owned frames/models/actions never receive the key or display plaintext. There is no `enc_eq` field, auxiliary index, backend decryptor, or persistent browser key. The outbound query grammar, persisted query-model encoding, projection, metadata requests, and telemetry belong to the [query design](./protected-attributes-query-design.md). This document owns browser crypto/key UI, a separate in-browser query-model sealing primitive, and read-only extraction of encrypted trace/search results into ephemeral pane state. The frozen contract in `local://protected-attributes-wire-contract.md` controls any conflicting example here.

The administrator configures only `TempoJsonData.protectedKeyId?: string`: 32 lowercase hex characters identifying the 32-byte key. A user separately imports the key in Explore. A protected datasource requires a matching imported key for protected literal queries; without one, reject such queries before any network request. Without a key, stock trace/search results retain ciphertext while the plugin pane shows locked placeholders for present protected attributes. Use one key per datasource and queryable retention window; mixed `kid` values and multi-key `!=` are not supported.

## Frozen bytes and browser crypto

- Decode a base64 text/file input, allowing padded or unpadded standard base64 and trimming only surrounding whitespace. Reject invalid characters, malformed padding and decoded lengths other than **32 bytes**. Do not accept a password/passphrase as a key.
- Compute `kid = hex_lower(SHA-256(master)[0:16])`. Web Crypto `subtle.digest` computes SHA-256; `subtle.importKey('raw', master, 'HKDF', false, ['deriveBits'])` and `deriveBits` produce **64 bytes** using HKDF-SHA256 with IKM=`master`, salt UTF-8 `tempo-attr-v1`, and info UTF-8 `aes-256-siv`. Fail import if Web Crypto is unavailable (ordinary HTTP outside localhost is not a supported secure context). Keep the derived bytes in the browser to use AES-SIV; a non-extractable Web Crypto AES key cannot implement this scheme.
- Pin a compatible `@noble/ciphers` version and import `aessiv` from `@noble/ciphers/aes.js`. Use RFC 5297 AES-256-SIV with that 64-byte derived key, one associated-data component, no nonce. Associated data for *each actual stored field name* is `UTF8('tempo:span:v1') || 0x00 || uint32be(byteLength(UTF8(storedField))) || UTF8(storedField)`. Use the exact bytes of `enc.password`, `enc.token`, etc., not the original name `password`. Encode plaintext with UTF-8; empty string is valid. The output bytes are the 16-byte SIV followed by ciphertext.
- The string stored in `enc.password` and used as a search equality literal is exactly `enc:v1:<kid>:<base64url_no_padding(SIV || ciphertext)>`. Reject unknown versions, bad syntax or base64url, truncated SIV, incorrect `kid`, wrong associated data/key, invalid UTF-8 plaintext, and authentication failures. Parse canonical envelopes rather than accepting alternate encodings. On success, identical key, stored name and plaintext must always produce identical envelope bytes.

## Separate encryption for Grafana query models

Grafana saves `TempoQuery.query` and builder `filters[].value` to its backend as part of dashboard/Explore state. The query owner seals the **entire valid raw query only if its parsed TraceQL contains protected references**, and seals each explicit protected Builder filter value; ordinary raw queries and ordinary filter values remain unchanged and usable without a key. An incomplete or ambiguous protected draft stays only in editor-local memory until valid, never in a host `onChange`. A protected literal must **not** remain plaintext in a saved model, even though the user edits plaintext locally. Do not use the deterministic attribute cipher (`enc:v1`) or its `tempo:span:v1` associated data as a storage wrapper: a query-model ciphertext is not a Tempo attribute value and must not become a TraceQL literal. This crypto slice provides the authenticated storage primitive; AST classification and selective model serialization belong to the [query design](./protected-attributes-query-design.md).

Derive an independent **32-byte AES-256-GCM model key** from the same imported 32-byte master with HKDF-SHA256, UTF-8 salt `tempo-query-model-v1`, and UTF-8 info `aes-256-gcm`. Import it into Web Crypto as a non-extractable `CryptoKey` for `encrypt`/`decrypt`, then zero the temporary derived bytes. This domain is separate from the 64-byte AES-SIV attribute key and does not alter its frozen vectors. For *each* seal, obtain a fresh 12-byte nonce from `crypto.getRandomValues`; Web Crypto AES-GCM uses a 128-bit tag. The AAD is `UTF8('tempo:query-model:v1') || 0x00 || uint32be(byteLength(UTF8(context))) || UTF8(context)`. Encode the UTF-8 model value as `qenc:v1:<kid>:<unpadded-base64url(nonce12 || ciphertext || tag16)>`. `openQueryModel` checks canonical envelope syntax/version/kid, minimum length, context binding, GCM authentication and fatal UTF-8 decoding. On any failure, reject with a value-free error; never display an unauthenticated draft or fall back to assuming the input was plaintext. This model envelope is randomized, unlike the searchable attribute envelope.

`context` is canonical `JSON.stringify` of a string array identifying the datasource UID and exact persisted slot: `[uid, 'query']`, `[uid, 'filters', filterId, 'value']`, or `[uid, 'filters', filterId, 'value', indexAsDecimalString]` for an array item. `uid` and `filterId` must be nonempty and filter IDs unique; the array representation avoids separator collisions. Do not bind `refId`, which Grafana may change when cloning a target. Moving a sealed value to another datasource or slot must fail authentication. Clearing the handle also invalidates the model key; a non-extractable Web Crypto key reduces accidental extraction but does not protect against XSS or revoke plaintext already rendered in a component.

## Cross-slice API and key lifecycle

Implement these exports in `src/protectedAttributes/crypto.ts` and `src/protectedAttributes/decrypt.ts`; the query owner consumes them from `src/datasource.ts`, without duplicating crypto or response traversal. `TraceSearchMetadata` comes from `src/types.ts`; the store and decrypted entries must remain inside browser-owned plugin memory:

```ts
export interface ProtectedAttributeKey {
  readonly kid: string;
  encrypt(storedField: string, plaintext: string): string;
  decrypt(storedField: string, envelope: string): string;
  sealQueryModel(plaintext: string, context: string): Promise<string>;
  openQueryModel(envelope: string, context: string): Promise<string>;
  clear(): void;
}
export function importKey(base64: string): Promise<ProtectedAttributeKey>;
export type ProtectedDisplayEntry = {
  traceID: string;
  spanID?: string;
  storedField: string;
  value: string;
  status: 'decrypted' | 'key-unavailable' | 'invalid-data';
};
export function extractProtectedDisplayEntries(
  response: DataQueryResponse,
  key?: ProtectedAttributeKey
): Promise<ProtectedDisplayEntry[]>;
export function extractProtectedSearchEntries(
  traces: readonly TraceSearchMetadata[],
  key?: ProtectedAttributeKey
): Promise<ProtectedDisplayEntry[]>;
export declare class ProtectedValuesStore {
  constructor(getEpoch: () => number);
  subscribe(listener: (entries: readonly ProtectedDisplayEntry[]) => void): () => void;
  snapshot(): readonly ProtectedDisplayEntry[];
  beginRequest(): number;
  replace(refId: string, entries: readonly ProtectedDisplayEntry[], keyEpoch: number, requestToken: number): void;
  clear(): void;
}
```

`importKey` asynchronously validates, hashes and derives both domain-separated keys once; attribute encryption/decryption after import are synchronous, while query-model sealing/opening use async Web Crypto. Each method throws/rejects with a typed, non-secret-bearing error on invalid input, a cleared key, invalid envelope, kid mismatch or failed authentication. `encrypt`/`decrypt` take a stored field including `enc.`; reject an unprefixed or empty name, not silently fix it. `sealQueryModel`/`openQueryModel` require the canonical, nonempty slot context above; they never accept a stored attribute name as associated data. A `clear()` call zeroes owned master/attribute-derived `Uint8Array`s, drops the model `CryptoKey` reference, and makes all four operations unusable. Avoid keeping extra copies and dispose temporary decoded buffers on success and failure. JS strings, browser/framework copies, noble internals, Web Crypto internals and old rendered frames cannot be reliably zeroed: this is best effort, not protection against XSS, extensions or compromised Grafana code.

The query owner implements the datasource bridge in **its** `src/datasource.ts`: expose a per-`TempoDatasource` read-only `protectedKey?: ProtectedAttributeKey`, `readonly protectedKeyEpoch: number`, `importProtectedKey(base64: string): Promise<string>` returning the new `kid`, `clearProtectedKey(): void`, `subscribeProtectedKey(listener: (epoch: number) => void): () => void` returning an unsubscribe function, and `readonly protectedValues = new ProtectedValuesStore(() => this.protectedKeyEpoch)`. Compare imported `kid` with configured `protectedKeyId` before replacing the current key; require a valid configured ID on protected datasources. On mismatch, report only the expected/actual IDs, discard the new handle, and retain the previous valid handle without broadcasting a false change. A successful replacement clears the previous handle. Increment the datasource-owned epoch, call `protectedValues.clear()`, and notify **all** key subscribers synchronously after each successful import/replacement or clear; expose only the epoch, never key material. Guard concurrent imports, pending model seals and in-flight extraction against this epoch: a late import, seal or result must not reinstate a key, save an obsolete model or show plaintext after clear/replacement. A datasource instance is the isolation boundary: never share handles between UIDs or persist them to JSON, `secureJsonData`, query models, URLs, local/session storage, cookies, Grafana state, backend requests or telemetry. Reload requires reimport. Clearing a key triggers all mounted editors to clear local import inputs/drafts and visible pane results; cached/copied plaintext outside this plugin cannot be recalled.

The display handoff is **read-only**. `extractProtectedDisplayEntries` inspects HTTP `DataQueryResponse` frames; `extractProtectedSearchEntries` inspects Live `TraceSearchMetadata[]` before the existing formatter. Both return new browser-only entries and leave the input object, field arrays, tags, nested JSON and Raw JSON untouched. Traverse only *actual stored `enc.` field names* in selected span attributes; never scan arbitrary strings for the `enc:v1:` prefix. A projected union-schema `null`/`undefined` means the attribute is absent: emit no entry, never a placeholder. For a present value, `status: 'decrypted'` carries the authenticated plaintext (including an empty string); a missing key emits `value: '[encrypted: key unavailable]'` and `status: 'key-unavailable'`; a bad kid, malformed envelope/version, non-string value, authentication or UTF-8 failure emits `value: '[encrypted: invalid data]'` and `status: 'invalid-data'`. Keep `storedField` (`enc.password`) and available trace/span IDs for pane identification. Do not put entry values in `DataQueryResponse`, DataFrames, field config or mappings, backend/host query models, links, metrics, telemetry, logs or errors.

`ProtectedValuesStore` belongs to the plugin and aggregates display entries **per `refId`**. `beginRequest()` runs once at the start of each datasource `query` call, increments a request token, clears all partitions and broadcasts an empty snapshot. `replace(refId, entries, capturedEpoch, token)` replaces only that target's partition and broadcasts a deterministic concatenation (stable refId order and source order within each partition); it ignores an obsolete token or epoch, but permits current-epoch keyless placeholder entries. HTTP targets can complete in any order without erasing each other; each full Live search emission replaces its own target partition rather than appending stale rows. `clear()` invalidates the token and wipes every partition. Subscriptions return an unsubscribe callback; store only current entries and do not replay decrypted results after import. In `datasource.ts`, capture key and epoch per request, pass the one token to every target, extract HTTP entries asynchronously before publishing them with `replace(target.refId, entries, epoch, token)`, then return the **original** encrypted response to Grafana without mutation. The Live call passes the optional fifth argument `displayRequestToken?: number` to `doTempoSearchStreaming(query, ds, options, settings, displayRequestToken)`; `streaming.ts` captures its starting epoch, extracts entries from each full Live snapshot and publishes `replace(query.refId, entries, epoch, token)` while returning the existing encrypted frames. Use ordered processing so later Live messages cannot overtake earlier ones. Errors do not publish partial decrypted entries.

### Strict host boundary and pane

Grafana [issue #117639](https://github.com/grafana/grafana/issues/117639) documents Table and BarChart “Filter for value” actions persisting **raw** DataFrame cell values as host-owned ad-hoc filters, bypassing this datasource's metadata suppression. `field.config.filterable: false` is not a general host-action guarantee; Grafana may recreate custom `field.display` processors, and `field.config.mappings` themselves carry plaintext inside a host frame. The stock trace viewer consumes raw `tags` through `DataFrameView`, not display mappings. Consequently, retain encrypted envelopes in all stock TraceView, Traces/Spans tables, BarChart and Raw JSON surfaces. Their protected values are intentionally ciphertext/locked, not secretly decrypted in host-owned frames.

`src/QueryField.tsx` renders a datasource-owned protected-values pane beside the query editor. It subscribes to `ds.protectedValues`, displays trace ID, optional span ID, actual stored field, and either authenticated `value` or its explicit locked/invalid marker. It is the **only** protected-plaintext display surface. Render values as escaped React text, never HTML, URLs or interpolation into a host callback. Pane content is browser-plugin-local React state, not a Grafana-owned DataFrame, field mapping, ad-hoc action, dashboard model, panel link, callback or telemetry payload. It has no host filter/copy/link action that writes plaintext to a host model. The pane clears on new query and key import/replacement/clear; importing a key does not resurrect previous results, so rerun the query to decrypt newly received data. Stock trace UI and pane necessarily differ: an encrypted trace tag remains encrypted in TraceView while its authenticated plaintext appears in the pane.

## UI and response-path placement

`src/configuration/ConfigEditor.tsx` adds an administrator-facing `protectedKeyId` setting in the existing configuration sections. Validate the lowercase 32-hex-character ID when present; blank means protection is not configured. Make it clear that this public fingerprint is not the key, and that enabling protection does not encrypt existing traces. Saving writes only `jsonData.protectedKeyId`. Do **not** put a key upload or input in datasource settings, which Grafana persists. `src/QueryField.tsx` shows a compact Explore status row with Load/Replace and Forget actions; a modal accepts either masked base64 paste or a local key file, never both. The dialog shows the full expected `kid`, clears transient input on cancel/import/key change, and tells users to rerun the query after loading. File bytes are read locally only on submission and imported through the datasource bridge; the key is lost on reload. A wrong key leaves the old valid key unchanged and shows a non-secret error. Explain the visible prefixes, deterministic equality leakage, unsupported unprefixed searches, and loss of key on reload without echoing key bytes into logs, telemetry, validation errors, or DOM text outside the transient masked input.

`QueryField.tsx` currently passes the raw `TempoQuery` to `QueryWithAssistantButton`. Under the strict design, protected plaintext exists in editor-local drafts but not newly saved query models; previously saved unsafe models may still exist. Neither must be sent to a remote assistant. When `jsonData.protectedKeyId` is configured, hide/disable that button entirely, even before key import; do not rely on query translation, a conditional scan of editor text, or the assistant feature toggle to sanitize it. Unprotected datasources keep their existing assistant behavior.

The query owner keeps protected raw/Builder plaintext only in local editor drafts within `src/traceql/QueryEditor.tsx`, `src/traceql/TraceQLEditor.tsx`, `src/SearchTraceQLEditor/TraceQLSearch.tsx` and `SearchField.tsx`. It opens a sealed saved query/filter with the imported key and awaits resealing **before** any `onChange` callback can reach Grafana. Parsed ordinary queries and ordinary filters stay plain and editable without the key; only valid protected raw queries and protected Builder values use `qenc:v1`. An incomplete or ambiguous draft remains unsaved in component memory and cannot run until a valid model is committed. A sealed saved model with no matching key shows a locked, non-editable editor and an import-key explanation, not an editable ciphertext literal, plaintext fallback, or a callback that overwrites the encrypted model. Discard protected drafts on unmount, key clear or key change. Every mounted `QueryField.tsx` subscribes to its datasource's `subscribeProtectedKey` on mount and unsubscribes on unmount or datasource replacement. On any epoch notification, immediately invalidate its decrypted draft and displayed results, clear transient input, and rerender/remount raw and Builder editors keyed by datasource UID plus `protectedKeyEpoch`; do not rely on a UI-local epoch that other instances cannot observe. Block `onRunQuery` while sealing is pending; ignore a seal completion after the captured datasource epoch changes. Before *every* host `onChange`, including query-type switch, `onClearResults` and `componentDidMount`, call the query-owned `src/protectedAttributes/model.ts` export `assertProtectedQueryModelSafe(query: TempoQuery, kid: string): void` with the configured `protectedKeyId`. It AST-classifies ordinary valid queries, accepts valid `qenc:v1` envelopes with the configured kid, and rejects unsealed protected/ambiguous/legacy fields. `QueryField` must not implement a second parser.

The render-time `nativeSearch` migration and Search-to-TraceQL copy path also call `onChange`; route them through the same validator/sealing boundary. A legacy plaintext protected saved model cannot be retroactively hidden from a dashboard already stored on Grafana's backend: detect it and lock/refuse re-save or dispatch until a key-holder explicitly migrates it to a sealed model. Do not silently persist the old plaintext again.

`ConfigEditor.tsx` also prevents configured static `search.filters` from storing a protected `span.enc.*` value in `TempoJsonData` when enabling protection or saving filters. An existing provisioned static filter can bypass the editor and therefore requires the query owner's runtime fail-closed guard before generation/dispatch. Grafana-owned ad-hoc filters and template-variable values may be persisted outside `TempoQuery`; the plugin cannot seal those host-owned models. The query owner must hide protected ad-hoc keys and reject any preexisting protected host ad-hoc filter or a template-variable RHS substituted into a protected predicate, before forwarding or claiming persistence safety. Ordinary ad-hoc filters and ordinary template variables retain existing behavior. Do not silently rewrite Grafana's global dashboard variable storage.

The actual static-filter write path is `src/configuration/TraceQLSearchTags.tsx:updateFilter`, which calls `updateDatasourcePluginJsonDataOption(..., 'search', { ...filters: copy })`; its delete/initialization paths also update the same JSON. The key UI/config doer owns this file along with `ConfigEditor.tsx`: validate the full prospective `search.filters` array before each save, including retained existing filters, so a span-scope `enc.*` default with a value cannot cross `onOptionsChange`. Do not mutate the input array or silently erase invalid values. Explain the offending field without repeating its value, and allow removing the invalid filter. The runtime gate still covers provisioned JSON that bypasses the editor.

Fail closed on **valued** static defaults whose `scope`, `tag`, or embedded query fragment contains a variable/expression or cannot be resolved to an exact unprotected attribute at save time. For example `{ scope: 'span', tag: '${attribute}', value: 'abc' }` is unsafe: `${attribute}` may later become `enc.password` after the plaintext `abc` has already been saved in datasource JSON. Reject the prospective config before `onOptionsChange`, and reject provisioned equivalents at runtime; do not try to classify only the current substituted value. A value-free static tag selector may remain available if it does not carry protected plaintext.

Metadata tag-value endpoints are owned by the [query design](./protected-attributes-query-design.md). Users enter their own protected values in the query editor; the outbound query owner encrypts only supported scoped span equality/inequality RHS literals after interpolation. Do not silently make the backend a plaintext metadata service.

## Security and failure decisions

AES-SIV is deterministic so native Tempo equality works on the *one* stored field. It reveals field names, equal-value frequency and approximate length; it does not protect nonselected attributes, trace IDs or other metadata. A random 32-byte key is mandatory. The chosen key ID is public and is not an authentication secret. No backend-only alert or direct Tempo client can transparently decrypt or translate protected literals. Clear the current key and imported inputs on user action, not only component unmount; unmounting the query editor must not accidentally clear a still-active datasource instance. Conversely, use an explicit key reset on datasource replacement/UID change and do not infer protection for `{span.password="abc"}`.

A wrong configured ID is a configuration/import error and must never be silently overridden. An invalid stored envelope is an individual display failure with a visible `[encrypted: invalid data]` marker, not an excuse to display unauthenticated bytes. A missing key shows `[encrypted: key unavailable]`; a protected literal query with no matching key fails closed before HTTP/Live dispatch. Under mixed-key historical traces, nonmatching rows show invalid-data markers; supported single-key queries cannot promise correct `!=` across rotations. Avoid swallowing errors from key import or wrapping them with secret text.
